## 1. 根因：开销在挂载元数据，不在模型推理

先 profile 再动手（脚本见 `perf/profile_predict.py`，日志 `cprofile-before.log`）：

- 容器内逐行调用 `contest_submission.predict` 600 行，cProfile 合计 **2.632 秒**；
- `posix.stat` 3600 次 **1.768 秒** + `posix.lstat` 1800 次 **0.503 秒**，即每行 6 次 stat + 3 次 lstat，
  占 86%，单次约 0.42 毫秒；
- 真正的推理（`tree_output` 120 棵树）只有 34 毫秒/600 行。

每行的元数据调用来自 `predict()` 里对挂载产物的重复校验：
`Path("/model").resolve()`、`checkpoint.is_symlink()`、`checkpoint.resolve()`、
`extension.is_symlink()`、`extension.is_file()`（两次）。`/model` 是宿主目录的**绑定挂载**，
本机是 Windows 盘经 9p/drvfs 进 WSL，元数据调用比容器本地磁盘慢两个数量级。

这也解释了队友包 `integration_report.json` 里 4 轮只花 73.88 秒：那个环境的 `/model` 在本地磁盘上，
同样 9 次调用几乎免费。**结论：此处不能靠“优化树推理”解决，之前试过的快速树遍历无效是必然的。**

## 2. 修复

修改文件：`contest_submission.py`（C/AB 共用的预测入口）。

```python
@lru_cache(maxsize=4)
def predict_target(model_dir, artifact_env):
    """Resolve and validate the mounted artifact once per process."""
    root = Path(model_dir).resolve()
    path = Path(artifact_env) if artifact_env is not None else root / NATIVE
    if not path.is_absolute():
        path = root / path
    if path.is_symlink() or not path.resolve().is_relative_to(root):
        raise ValueError("selected checkpoint must be within /model")
    extension = root / EXTENSION
    if extension.is_symlink():
        raise ValueError("extension must be a regular mounted file")
    return path, path.relative_to(root).as_posix(), extension, extension.is_file()
```

`predict()` 每行只做字典命中 + 描述符字符串比对，不再触碰文件系统。

为什么语义不变：

- `/model` 是只读绑定挂载，一次预测流内不可能变化，也不可能有第二个模型；
- 缓存键是（挂载目录字符串，`CONTEST_ARTIFACT_PATH`）。越界路径、软链接、扩展文件存在性、
  描述符不符这些拒绝**全部保留**，且异常不会被缓存（每行都会照样抛）；
- 新增 `tests/test_c_predict_target.py` 6 条契约测试：软链接 checkpoint、软链接 extension、
  越界路径（绝对路径/相对逃逸）、描述符缺少扩展、描述符多写扩展、校验只跑一次、
  以及“缓存后预测值与直接 `load().predict` 一致”。
